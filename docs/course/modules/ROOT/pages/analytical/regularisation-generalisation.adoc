Regularisation trades training fit for constrained model complexity and stability. Ridge shrinks correlated coefficients continuously; Lasso can set coefficients to zero but its selected feature among correlated alternatives may be unstable.

== Penalised objectives

Assume the columns of stem:[X] have been scaled inside the fitted pipeline.

.Definition: Ridge estimator
[.def#def:ridge]
****
[stem]
++++
\widehat\beta_{\mathrm{ridge}}(\lambda)
=\operatorname*{argmin}_{\beta}
\left\{\frac1n\lVert y-X\beta\rVert_2^2
+\lambda\lVert\beta\rVert_2^2\right\},
\qquad \lambda\ge0.
++++

For the stated scaling of the loss,

[stem]
++++
\widehat\beta_{\mathrm{ridge}}
=\left(X^\top X+n\lambda I\right)^{-1}X^\top y.
++++
****

.Definition: Lasso estimator
[.def#def:lasso]
****
[stem]
++++
\widehat\beta_{\mathrm{lasso}}(\lambda)
=\operatorname*{argmin}_{\beta}
\left\{\frac1n\lVert y-X\beta\rVert_2^2
+\lambda\lVert\beta\rVert_1\right\}.
++++

The stem:[\ell_1] objective is convex but not differentiable at zero. Its geometry can produce exact zero coefficients; it does not prove that the remaining variables are causal or uniquely important.
****

For the displayed objectives, scikit-learn's `Ridge` uses `alpha = n_train * lambda`, whereas `Lasso` uses `alpha = lambda / 2`. The grids below tune the library's `alpha`. For Ridge, a fixed alpha therefore corresponds to a different lambda when the training size changes (144 rows per CV fit, 180 in the final refit here). Keep that convention explicit when comparing formulae and software.

The intercept is normally left unpenalised. Without scaling, the same stem:[\lambda] penalises coefficients attached to differently scaled features unequally.

== Bias–variance mathematics

For a fitted predictor stem:[\widehat f] and a new response stem:[Y=f(x)+\varepsilon] with stem:[\mathbb E\varepsilon=0] and stem:[\operatorname{Var}(\varepsilon)=\sigma^2], the pointwise expected squared prediction error is

[stem]
++++
\mathbb E_{\mathcal D,\varepsilon}
\left[(Y-\widehat f_{\mathcal D}(x))^2\right]
=\sigma^2
+\left(\mathbb E_{\mathcal D}\widehat f_{\mathcal D}(x)-f(x)\right)^2
+\operatorname{Var}_{\mathcal D}(\widehat f_{\mathcal D}(x)).
++++

The three terms are irreducible noise, squared bias, and training-sample variance. Increasing regularisation usually raises bias and lowers variance, but the balance depends on stem:[x], sample size, feature geometry, and the true signal.

== Generalisation diagnosis

Bias and variance describe expected error behaviour across possible training samples, not a visual slogan about one curve. Learning curves compare training and validation evidence as sample size changes. Hyperparameters are selected inside cross-validation; the final test remains outside the entire selection process.

Scale features inside the fitted pipeline before applying coefficient penalties. Report coefficient paths as conditional predictive behaviour, not automatic causal importance.

== Error estimation

Cross-validation compares candidate pipelines only when learned preprocessing and feature selection occur inside each training fold. The winning CV score is used for selection and can be optimistic; evaluate the selected procedure on a protected test or with an outer CV loop. Report the fold distribution and repeat the outer split when feasible. Overlapping training folds make fold scores dependent, so a naive stem:[s/\sqrt K] interval should not be presented as exact.

For feature stability, define a selection indicator stem:[I_{jb}=1] if feature stem:[j] is non-zero in resample stem:[b]. The empirical selection frequency

[stem]
++++
\widehat\pi_j=\frac1B\sum_{b=1}^{B}I_{jb}
++++

describes algorithmic stability under the chosen resampling design. It is not a posterior inclusion probability and does not correct confounding.

Learning curves estimate how training and validation risk change with sample size. Their variation across resamples is as important as the mean; one curve from nested subsets can hide sample sensitivity.

[.worked-example-method#worked-regularisation-method]
=== Method

*Importance:* Core (P1)

.Example: Ridge shrinkage in an orthogonal design
[.examp#ex:ridge-orthogonal]
****
Suppose stem:[X^\top X=nI] and define the unregularised estimate stem:[\widehat\beta_{\mathrm{ols}}=X^\top y/n]. Then

[stem]
++++
\widehat\beta_{\mathrm{ridge}}
=\frac{1}{1+\lambda}\widehat\beta_{\mathrm{ols}}.
++++

Every coefficient is shrunk by the same factor. For stem:[\lambda=1], the coefficients are halved. For example, if stem:[\widehat\beta_{\mathrm{ols}}=(2,-1)^\top], then

[stem]
++++
\widehat\beta_{\mathrm{ridge}}(1)
=\frac12(2,-1)^\top=(1,-0.5)^\top,
\qquad
\lVert\widehat\beta_{\mathrm{ridge}}\rVert_2
=\frac12\lVert\widehat\beta_{\mathrm{ols}}\rVert_2.
++++

Both coordinates and the coefficient norm are halved, while training residual error generally increases because Ridge optimises a different objective. In a correlated design the shrinkage acts along singular-vector directions and is not a coordinate-wise halving.
****

.Mathematical insight — regularisation changes the estimator to trade bias for variance
[IMPORTANT]
====
[.notebook-insight-label]
*Mathematical insight.*

*Core (P1).* In an orthogonal design, Ridge applies the filter stem:[1/(1+\lambda)] to every coefficient; in a general design, singular direction stem:[j] is filtered according to its information and penalty scale. Shrinkage introduces bias but can reduce estimation variance and prediction error. It does not merely repair a numerical solver, and Lasso zeros do not prove that the retained coordinates are uniquely causal.
====

import numpy as np
import pandas as pd
from sklearn.linear_model import Lasso, LinearRegression, Ridge
from sklearn.metrics import root_mean_squared_error
from sklearn.model_selection import GridSearchCV, KFold, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

# Generate a known quadratic signal with noise, then protect one test split.
rng = np.random.default_rng(20260722)
x = rng.uniform(-2.0, 2.0, size=(240, 1))
y = 1.0 - 2.0 * x[:, 0] + 0.8 * x[:, 0] ** 2 + rng.normal(scale=1.0, size=len(x))
X_train, X_test, y_train, y_test = train_test_split(
    x, y, test_size=0.25, random_state=20260722
)
penalties = np.logspace(-4, 3, 18)
# Search wraps every learned preprocessing step: validation rows never fit the scaler.
selection_cv = KFold(5, shuffle=True, random_state=20260722)
ridge_search = GridSearchCV(
    make_pipeline(PolynomialFeatures(12, include_bias=False), StandardScaler(), Ridge()),
    {"ridge__alpha": penalties},
    cv=selection_cv, scoring="neg_root_mean_squared_error", n_jobs=1,
).fit(X_train, y_train)
lasso_search = GridSearchCV(
    make_pipeline(
        PolynomialFeatures(12, include_bias=False), StandardScaler(),
        Lasso(max_iter=100000, random_state=20260722),
    ),
    {"lasso__alpha": np.logspace(-3, 0, 18)},
    cv=selection_cv, scoring="neg_root_mean_squared_error", n_jobs=1,
).fit(X_train, y_train)
ridge = ridge_search.best_estimator_
lasso = lasso_search.best_estimator_
ridge_model = ridge.named_steps["ridge"]
lasso_model = lasso.named_steps["lasso"]
unregularised = make_pipeline(
    PolynomialFeatures(12, include_bias=False), StandardScaler(), LinearRegression()
).fit(X_train, y_train)
unregularised_rmse = float(root_mean_squared_error(y_test, unregularised.predict(X_test)))
ridge_rmse = float(root_mean_squared_error(y_test, ridge.predict(X_test)))
lasso_rmse = float(root_mean_squared_error(y_test, lasso.predict(X_test)))
assert ridge_rmse < 1.5 and lasso_rmse < 1.5
assert np.count_nonzero(lasso_model.coef_) < len(lasso_model.coef_)

regularisation_summary = pd.DataFrame(
    {
        "selected penalty": [0.0, ridge_model.alpha, lasso_model.alpha],
        "protected-test RMSE": [unregularised_rmse, ridge_rmse, lasso_rmse],
        "non-zero coefficients": [
            int(np.count_nonzero(unregularised.named_steps["linearregression"].coef_)),
            int(np.count_nonzero(ridge_model.coef_)),
            int(np.count_nonzero(lasso_model.coef_)),
        ],
    },
    index=["Unregularised", "Ridge", "Lasso"],
)
regularisation_summary

Finally, predict which model will vary most across fresh training samples. We independently simulate 48 datasets of 40 observations from the same quadratic signal, with noise standard deviation 1. At a fixed interior grid, the finite-sample identity below separates squared bias and variance of the fitted predictions. Adding the *known* noise variance gives expected error for a fresh noisy response under this oracle; it is not a decomposition estimated from a real industrial dataset.

[#bias-variance-table]
[%dynamic%open,python,fail-on-error=,output=table,table-caption="Repeated-training-sample bias–variance experiment",table-description="Four model specifications report grid-averaged squared bias, prediction variance, known noise variance, and their sum over 48 independent training datasets."]
----
from sklearn.base import clone

oracle_rng = np.random.default_rng(20260905)
oracle_grid = np.linspace(-1.8, 1.8, 160).reshape(-1, 1)
def signal(values):
    return 1.0 - 2.0 * values[:, 0] + 0.8 * values[:, 0] ** 2

specifications = {
    "linear least squares": make_pipeline(PolynomialFeatures(1, include_bias=False), StandardScaler(), LinearRegression()),
    "quadratic least squares": make_pipeline(PolynomialFeatures(2, include_bias=False), StandardScaler(), LinearRegression()),
    "degree 12 least squares": make_pipeline(PolynomialFeatures(12, include_bias=False), StandardScaler(), LinearRegression()),
    "degree 12 Ridge (alpha 1)": make_pipeline(PolynomialFeatures(12, include_bias=False), StandardScaler(), Ridge(alpha=1.0)),
}
predictions = {name: [] for name in specifications}
for repetition in range(48):
    draw_x = oracle_rng.uniform(-2.0, 2.0, size=(40, 1))
    draw_y = signal(draw_x) + oracle_rng.normal(scale=1.0, size=40)
    for name, estimator in specifications.items():
        predictions[name].append(clone(estimator).fit(draw_x, draw_y).predict(oracle_grid))

rows = []
for name, values in predictions.items():
    values = np.asarray(values)
    squared_bias = float(np.mean((values.mean(axis=0) - signal(oracle_grid)) ** 2))
    variance = float(np.mean(values.var(axis=0, ddof=0)))
    error_to_signal = float(np.mean((values - signal(oracle_grid)) ** 2))
    assert np.isclose(error_to_signal, squared_bias + variance, rtol=1e-10, atol=1e-10)
    rows.append([name, squared_bias, variance, 1.0, squared_bias + variance + 1.0])
bias_variance_evidence = pd.DataFrame(rows, columns=["model", "squared bias", "variance", "known noise", "expected noisy-response MSE"])
bias_variance_evidence
----

These are finite-repeat estimates: extreme polynomial fits can dominate their averages. Repeat under another seed and inspect fitted curves before generalising the ordering. Change *one* of sample size, noise, degree, or penalty and rerun. Use the known signal to explain the changed decomposition; do not infer bias from the appearance of one fitted curve.

[.worked-example-conclusion#worked-regularisation-conclusion]
=== Conclusion

*Importance:* Essential (P0)

Regularisation can trade a modest increase in bias for more stable prediction, but Ridge and Lasso encode different structural preferences. The penalty path illustrates shrinkage, while the protected test compares the prespecified fitted procedures. Repeated training samples expose variability that a single curve cannot show. Minimum error and minimum coefficient norm answer different questions. The selected penalty remains uncertain, and correlated predictors make coordinate paths basis-dependent; this supports a predictive-stability claim, not a causal coefficient interpretation.
