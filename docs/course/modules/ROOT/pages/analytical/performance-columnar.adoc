Efficient processing starts with an estimate: rows × columns × bytes, temporary copies, and algorithmic cost. Measure representative work before changing engines. Distribution is not a remedy for unnecessary materialisation.

CSV loses types and requires parsing; Parquet stores typed columns with compression and statistics. An analytical engine can project columns, filter rows, and aggregate before returning a small DataFrame. This is query pushdown, not a replacement for database theory.

== Cost model

Let a table contain stem:[n] rows and selected columns stem:[j\in S] with physical widths stem:[b_j] bytes. A lower-bound payload estimate is

[stem]
++++
M_{\mathrm{payload}}=n\sum_{j\in S}b_j.
++++

.Definition: Peak-memory budget
[.def#def:peak-memory]
****
A useful first model is

[stem]
++++
M_{\mathrm{peak}}
\approx M_{\mathrm{input}}+M_{\mathrm{output}}+M_{\mathrm{temporary}}+M_{\mathrm{runtime}}.
++++

Object headers, null bitmaps, string offsets/data, indexes, decompression buffers, copies, and hash tables make peak memory larger than raw payload.
****

For a scan that reads stem:[B] bytes from storage bandwidth stem:[q] bytes/s, stem:[T\ge B/q] even before parsing or computation. Projection and predicate pushdown reduce stem:[B]; changing syntax without reducing work does not.

If a parallel fraction stem:[a] is accelerated by stem:[s] while fraction stem:[1-a] remains serial, Amdahl's model gives

[stem]
++++
S_{\mathrm{total}}\le\frac{1}{(1-a)+a/s}.
++++

It explains why distributing a workflow with dominant I/O, serial parsing, or data transfer may add overhead without useful speedup.

== Columnar execution

For an analytical query stem:[Q=\gamma\circ\sigma\circ\pi]—projection stem:[\pi], selection stem:[\sigma], then aggregation stem:[\gamma]—a lazy engine can move stem:[\pi] and stem:[\sigma] close to the file scan. Correctness requires that the reordered plan preserve null, type, predicate, and aggregation semantics.

Parquet row-group statistics may prove that a group cannot satisfy a predicate, allowing it to be skipped. Compression changes both bytes read and CPU decompression work; smaller files are not automatically faster for every query.

== Error estimation for benchmarks

Let stem:[T_1,\ldots,T_r] be repeated elapsed times after a declared warm-up. Report median and spread, environment, workload, and result equality. Under a stable approximately independent benchmark process, the standard error of the mean is stem:[s_T/\sqrt r], but operating-system scheduling, caches, thermal behaviour, and background work often violate that simple model.

For paired alternatives run in interleaved order and examine log ratios

[stem]
++++
d_i=\log\frac{T_{A,i}}{T_{B,i}}.
++++

The exponentiated mean/median describes a relative factor. A performance conclusion must be bounded to the tested data, query, machine, versions, and cache state. Runtime remains ungraded.

=== Context

A processing task must fit within a 4 GiB memory budget while selecting only seven columns from a much wider table. Estimate feasibility before execution, then test whether typed columnar storage and projection preserve the result on a bounded workload.

[.worked-example-method#worked-performance-method]
=== Method

*Importance:* Core (P1)

.Example: Memory estimate before execution
[.examp#ex:memory-estimate]
****
A table has stem:[n=10^7] rows, four `float64` columns, two `int32` columns, and a one-byte boolean. The raw selected payload is

[stem]
++++
10^7\left(4\times8+2\times4+1\right)
=4.1\times10^8\ \text{bytes}\approx391\ \text{MiB}.
++++

Reading the complete 40-column table, creating a boolean mask, and copying filtered rows can exceed a 4 GiB budget even though the seven-column payload fits. Projection before materialisation changes the feasibility of the workflow.
****

.Mathematical insight — payload is a lower bound on peak memory
[IMPORTANT]
====
[.notebook-insight-label]
*Mathematical insight.*

*Core (P1).* The sum stem:[n\sum_j b_j] counts only raw selected values. Peak memory also includes validity bitmaps, offsets, indexes, decoded strings, masks, copies, and intermediates. Projection and predicate pushdown reduce terms before materialisation; a faster file format cannot compensate for an algorithm that constructs an unnecessarily large intermediate relation.
====

=== Implementation

*Importance:* Essential (P0)

The hand estimate establishes that the seven selected raw columns require approximately 391 MiB before container and temporary-object overhead. The executable extension scales the air-quality slice to a bounded workload, writes CSV and Parquet, projects three columns, and verifies a filtered DuckDB aggregation against pandas. The table reports bytes and result equality; the figure compares artifact sizes without pretending that file size is a timing benchmark.

----
import tempfile
from pathlib import Path

import duckdb
import pandas as pd

def course_file(relative: str) -> Path:
    """Locate canonical data in a repository checkout or student bundle."""
    for root in [Path.cwd(), *Path.cwd().parents]:
        candidate = root / relative
        if candidate.is_file():
            return candidate
    raise FileNotFoundError(relative)


data_path = course_file("datasets/teaching/air-quality/observations.csv")
source = pd.read_csv(data_path)

# Replication creates a deterministic moderate workload without printing the table.
expanded = pd.concat(
    [source.assign(replicate=index) for index in range(50)], ignore_index=True
)
expanded["observation_id"] = range(len(expanded))


def columnar_evidence(frame: pd.DataFrame) -> dict[str, object]:
    """Compare bounded artifacts and verify query-result equivalence."""
    with tempfile.TemporaryDirectory() as directory_name:
        directory = Path(directory_name)
        csv_path = directory / "air.csv"
        parquet_path = directory / "air.parquet"
        frame.to_csv(csv_path, index=False)
        frame.to_parquet(parquet_path, index=False)

        # Projection avoids materialising unused pollutant and weather columns.
        projected_columns = ["station", "PM2.5", "replicate"]
        projected = pd.read_parquet(parquet_path, columns=projected_columns)
        pandas_result = (
            projected.query("station == 'Dingling'")
            .groupby("replicate")["PM2.5"]
            .mean()
            .sort_index()
        )
        query = """
            SELECT replicate, avg("PM2.5") AS mean_pm25
            FROM read_parquet(?)
            WHERE station = 'Dingling'
            GROUP BY replicate
            ORDER BY replicate
        """
        duck_result = (
            duckdb.execute(query, [str(parquet_path)])
            .fetchdf()
            .set_index("replicate")["mean_pm25"]
        )
        csv_bytes = csv_path.stat().st_size
        parquet_bytes = parquet_path.stat().st_size
        return {
            "rows": len(frame),
            "CSV bytes": csv_bytes,
            "Parquet bytes": parquet_bytes,
            "Parquet / CSV": parquet_bytes / csv_bytes,
            "projected columns": ", ".join(projected_columns),
            "query result rows": len(duck_result),
            "rounded results equal": bool(
                pd.Series(pandas_result).round(10).equals(duck_result.round(10))
            ),
        }


storage_evidence = columnar_evidence(expanded)
assert storage_evidence["rows"] == 50_400
assert storage_evidence["Parquet bytes"] < storage_evidence["CSV bytes"]
assert storage_evidence["rounded results equal"]
pd.DataFrame.from_dict(storage_evidence, orient="index", columns=["value"])
----

[.worked-example-conclusion#worked-performance-conclusion]
=== Conclusion

*Importance:* Essential (P0)

Projection makes the selected payload compatible with the stated memory budget, and Parquet reduces storage for this controlled schema. The hand calculation remains a lower bound because runtime structures and temporaries add memory. A smaller Parquet file does not prove a universal speedup; timing evidence additionally requires warm-up, repeated paired measurements, environment identity, and exact result agreement.
