This compact bridge translates familiar NumPy reasoning into JAX transformations. It is optional, CPU-compatible, and excluded from controls and examinations. Removing it leaves the complete 28-hour Essential/Core (P0/P1) course unchanged.

== Learning contract

After the lab you should be able to:

* distinguish JAX arrays and pure numerical functions from mutable notebook state;
* own randomness explicitly by creating, splitting, and passing PRNG keys;
* compute a gradient with `grad` or `value_and_grad` and challenge it with finite differences;
* explain the compilation boundary of `jit`, including shape/dtype specialisation and first-call cost;
* replace a Python batch loop with `vmap` and verify result equality.

The lab does not teach neural-network construction, PyTrees, Optax, accelerator setup, or long training loops. Those belong to the xref:extensions/downstream-paths.adoc[Scientific Machine Learning hand-off].

== Mathematical background

For a differentiable scalar function stem:[f:\mathbb R^p\to\mathbb R], reverse-mode automatic differentiation evaluates the vector

[stem]
++++
\nabla f(\theta)
=
\left(
\frac{\partial f}{\partial\theta_1},
\ldots,
\frac{\partial f}{\partial\theta_p}
\right)^\top
++++

by differentiating the program's primitive operations. It computes the derivative of the implemented program; it does not prove that the program represents the intended scientific model.

A central finite-difference challenge for coordinate stem:[j] is

[stem]
++++
g_j^{(h)}
=
\frac{f(\theta+h e_j)-f(\theta-h e_j)}{2h}.
++++

For a smooth function, truncation error is stem:[O(h^2)], while floating-point cancellation grows as stem:[h] becomes too small. Gradient verification therefore compares several plausible step sizes and uses absolute and relative tolerances.

Vectorisation applies one pure function across a batch:

[stem]
++++
\operatorname{vmap}(f)(x_1,\ldots,x_n)
=
\bigl(f(x_1),\ldots,f(x_n)\bigr),
++++

subject to the declared mapped axes. Equality with a small scalar loop is a useful oracle before performance claims.

== Verification discipline

Automatic differentiation differentiates the program that was written. It does not establish that the program represents the intended model. Use a tiny deterministic oracle, compare against central differences, check shapes and dtypes, and then test a transformed batch against a simple scalar version.

Compilation timing is descriptive only. Warm up deliberately, synchronise asynchronous results when benchmarking, and never infer an algorithmic speedup from a single first call.

== Error estimation

For each checked coordinate, report the absolute discrepancy stem:[|g_j-g_j^{(h)}|] and a scale-aware relative discrepancy such as

[stem]
++++
\frac{|g_j-g_j^{(h)}|}
{\max(1,|g_j|,|g_j^{(h)}|)}.
++++

Passing this numerical check supports local implementation correctness for the selected point and steps. It does not establish differentiability everywhere, statistical validity, or correctness of the loss definition.

== Transfer

Implement the stable binary logistic loss from the Core (P1) curriculum with `jax.numpy`. Compute and verify one parameter gradient, vectorise per-example losses and gradients, and record the function's inputs, output shape, dtype, PRNG ownership, and compilation boundary.
