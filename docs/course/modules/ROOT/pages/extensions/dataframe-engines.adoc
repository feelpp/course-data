== Same question, three plans

Use the teaching air-quality Parquet table and compute daily PM2.5 summaries for selected stations and dates.

[cols="2,3,3",options="header"]
|===
|Engine |Natural plan |Evidence to inspect
|pandas |Projected Parquet read followed by filtering and group-by |Materialised shape, dtypes, peak memory, result index
|DuckDB |SQL scan with projection, predicate, and aggregation pushdown |Query plan, selected columns, filtered rows, Arrow/pandas transfer
|Polars |Lazy `scan_parquet`, expressions, group-by, then `collect` |Optimised lazy plan, selected columns, filtered rows, streaming suitability
|===

The https://duckdb.org/docs/stable/data/parquet/overview.html[DuckDB Parquet documentation] and https://docs.pola.rs/user-guide/lazy/using/[Polars lazy API guide] describe pushdown and lazy execution. The optional environment pins Polars `1.42.1`; DuckDB remains part of the core environment.

== Fair experiment contract

. Assert identical key sets, grouping semantics, missing-value treatment, units, ordering, and numerical tolerance.
. Separate file parsing, query execution, and conversion to a client dataframe.
. Record versions, files, columns, filters, repetitions, warm-up, and peak memory.
. Use the same local file and fixed data budget.
. Treat timing as evidence tied to this workload and machine, not as a grading target.

== Mathematical limits

If a plan must read stem:[B] bytes from storage with sustained bandwidth stem:[b], its elapsed time satisfies the physical lower bound

[stem]
++++
T\ge \frac{B}{b}.
++++

Projection and predicate pushdown reduce the bytes that cross a storage or memory boundary. They cannot make a required scan cheaper than the selected bytes, and a lower scan volume does not guarantee a faster end-to-end query once parsing, compilation, aggregation, conversion, and cache effects are included.

For a materialised table with stem:[n] rows and fixed-width column sizes stem:[w_1,\ldots,w_p], the raw payload is at least

[stem]
++++
n\sum_{j=1}^{p}w_j\ \text{bytes},
++++

before validity bitmaps, offsets, object overhead, indexes, temporary arrays, and copies. Measure peak memory rather than quoting this lower bound as a complete forecast.

== Selection rule

Choose pandas for small in-memory transformations and broad ecosystem interoperability, DuckDB for SQL-centred analytical pushdown and multi-file queries, and Polars when expression-based lazy dataframe plans fit the team and workload. Operational familiarity, debuggability, deployment constraints, and result correctness matter alongside speed.

Database theory and relational design continue in xref:extensions/downstream-paths.adoc[the Database hand-off]; distributed execution belongs to HPC rather than this local-engine comparison.
