The unit of analysis must survive every selection, reshape, aggregation, and join. A table that looks plausible can still be wrong when keys multiply rows or when storage types hide semantic errors.

The mathematical object behind a table matters: rows index observational units, columns represent variables, and keys define identity. Array and aggregation errors can therefore change the estimand, not merely the file layout. The notation follows xref:foundations/mathematical-background.adoc[Mathematical background and error estimation].

== What you must be able to do

* reason about array shapes, dtypes, masks, broadcasting, and reductions;
* distinguish an index from a domain key and declare the unit of analysis;
* convert between long/tidy and wide forms without accidental aggregation;
* group and aggregate with explicit output keys and units;
* declare join cardinality before merging and validate it in code;
* preserve row/key evidence and report unmatched records.

== Core contracts

A tidy row is one observation of the declared unit; a column is one variable; a table is one observational level. This is a reasoning convention, not a demand that every stored artifact have one physical layout.

For a join, write the expected relationship first: one-to-one, one-to-many, many-to-one, or intentional many-to-many. In pandas, use `validate=` where possible, inspect key uniqueness on both sides, record unmatched keys, and compare the pre/post key set. Row-count equality alone is insufficient: one row can be lost while another is duplicated.

Storage dtype is not semantics. An integer may be an identifier, a float may carry a physical unit, and a string may encode an ordered category or timestamp. Record types, units, category vocabulary, nullability, and timezone alongside the code.

== Array shapes and reductions

For stem:[X\in\mathbb R^{n\times p}], rows index stem:[n] observational units and columns index stem:[p] variables. A column mean is

[stem]
++++
\bar x_j=\frac1n\sum_{i=1}^{n}X_{ij},
++++

whereas a row mean averages different variables and often has no scientific meaning. Broadcasting a vector stem:[a\in\mathbb R^p] across rows produces stem:[Y_{ij}=X_{ij}+a_j]; the shape is valid only if this per-variable operation matches units and semantics.

.Definition: Join multiplicity
[.def#def:join-multiplicity]
****
For join key stem:[k], let stem:[m_L(k)] and stem:[m_R(k)] be its multiplicities in left and right tables. An inner equality join produces

[stem]
++++
N_{\mathrm{join}}=\sum_{k}m_L(k)m_R(k)
++++

rows. A key duplicated twice on each side produces four joined rows. The formula explains why an unintended many-to-many join can silently reweight later summaries.
****

== Aggregation and error

If group stem:[g] has stem:[n_g] observations and mean stem:[\bar x_g], the global mean is the size-weighted quantity

[stem]
++++
\bar x=\frac{\sum_g n_g\bar x_g}{\sum_g n_g},
++++

not the unweighted mean of group means unless all group sizes are equal or the target population gives groups equal weight. Standard deviation describes variation among observations; standard error describes uncertainty of an estimator. Aggregating hourly measurements to daily means changes both the observational unit and the dependence structure.

== Hand calculation: join amplification

.Example: Join amplification
[.examp#ex:join-amplification]
****
For key A, the left table has two rows and the right table three; for key B, each has one. The inner join contains stem:[2\times3+1\times1=7] rows. A mean computed after this join weights A six times and B once. If the intended unit was one key, the result answers the wrong question even though the merge succeeds.
****

[.notebook-insight-label]
*Mathematical insight.*

*Essential (P0).* For a many-to-one enrichment join, each observation key should map to exactly one registry row. The key set and row count are invariants: unexpected multiplication proves that the declared relation is false or the registry key is not unique. A successful SQL or pandas call is not evidence of semantic correctness without these cardinality checks.

from pathlib import Path

import pandas as pd

# These Antora attachment references become notebook-relative dataset paths.
def course_file(relative: str) -> Path:
    """Locate canonical data in a repository checkout or student bundle."""
    for root in [Path.cwd(), *Path.cwd().parents]:
        candidate = root / relative
        if candidate.is_file():
            return candidate
    raise FileNotFoundError(relative)


observations_path = course_file("datasets/teaching/air-quality/observations.csv")
stations_path = course_file("datasets/teaching/air-quality/stations.csv")
observations = pd.read_csv(observations_path)
stations = pd.read_csv(stations_path)


def prepare_tables(
    observations: pd.DataFrame, stations: pd.DataFrame
) -> tuple[pd.DataFrame, pd.DataFrame]:
    """Construct the observation key, tidy pollutants, and validate provenance join."""
    frame = observations.copy()
    frame["timestamp"] = pd.to_datetime(frame[["year", "month", "day", "hour"]])
    key = ["station", "timestamp"]
    if frame.duplicated(key).any():
        raise ValueError("Observation key is not unique")

    pollutants = frame.melt(
        id_vars=key,
        value_vars=["PM2.5", "PM10", "NO2"],
        var_name="pollutant",
        value_name="concentration",
    )
    before = set(map(tuple, frame[key].itertuples(index=False, name=None)))
    joined = frame.merge(
        stations, on="station", how="left", validate="many_to_one", indicator=True
    )
    after = set(map(tuple, joined[key].itertuples(index=False, name=None)))
    if before != after or not joined["_merge"].eq("both").all():
        raise ValueError("Join changed or failed to match observation keys")
    return joined.drop(columns="_merge"), pollutants


joined, pollutants = prepare_tables(observations, stations)
assert joined[["station", "timestamp"]].duplicated().sum() == 0
assert len(joined) == len(observations)
assert set(pollutants["pollutant"]) == {"PM2.5", "PM10", "NO2"}
assert len(pollutants) == 3 * len(observations)
joined[["station", "timestamp", "PM2.5", "source_file"]].head()
----
