Follow this page before running the course notebooks on your computer. We use *Python 3.12*, *uv* to install Python libraries, and *Visual Studio Code* to work with notebooks. The green *Download bundle* button provides the files we need. Git, Node.js and npm are not required for this setup.

Allow about 30 minutes and an Internet connection for the first installation. The reference environment is CPython 3.12 on Ubuntu 24.04 LTS; the commands below also cover macOS and Windows. A GPU is not required for Essential (P0) or Core (P1) work.

== Before the commands: what do these names mean?

Suppose the course examples use a particular version of pandas, while another project on your computer needs a different version. We want to keep both projects working and give everyone in the class the same library versions. The following tools and files help us do that.

[cols="1,2,4",options="header"]
|===
|Name |What it is |Its role here
|*uv*
|A program you run in the terminal.
|It finds or downloads Python, creates an environment and installs libraries. It is a tool that manages the installation; it is not Python or pandas.
|*Virtual environment* (often shortened to *venv*)
|A Python interpreter with a separate set of installed libraries for one project.
|It lets this course use its own versions without changing the libraries used by your other projects. It runs locally on your computer; it is not a remote machine.
|*`uv venv`*
|A command given to uv.
|It creates a virtual environment. In our command `uv venv --python 3.12`, `--python 3.12` requests the Python version used by the course.
|*`.venv`*
|A folder created inside your extracted bundle.
|This is where the environment's Python and installed libraries live. The leading dot is part of its name. Your notebooks remain in `notebooks/`, outside this folder.
|*`pyproject.toml`*
|A text file describing the Python project and its requirements.
|It lists the Python version and libraries the course needs. *TOML* is the format used to write this configuration: section names, names and values. You can read it in VS Code; it is not a Python script to execute.
|*`uv.lock`*
|A text file generated by uv and supplied in the bundle, recording the precise library versions to install.
|It also records the libraries needed by other libraries, called *dependencies*. It lets uv repeat the same installation. This is a file supplied in the bundle, not a command named “uvlock”.
|*`.python-version`*
|A small text file containing `3.12`.
|It tells uv which Python version to select for this project.
|===

Python also has a built-in module named `venv` that can create virtual environments. In this course we use `uv venv` for that job; there is no second environment to create with `python -m venv`.

For example, these lines appear in the bundle's `pyproject.toml` (other libraries are omitted here):

[source,toml]
----
[project]
requires-python = ">=3.12,<3.13"
dependencies = [
  "numpy==2.3.2",
  "pandas==2.3.1",
]
----

`[project]` starts a section. `requires-python` requests Python 3.12, including its maintenance updates, but excludes Python 3.13. The list after `dependencies` names libraries; `==` requests an exact version. Here the course already specifies versions for its main libraries. `uv.lock` records the full installation, including their dependencies. *Read these files to understand them; use the supplied copies for installation.*

The sequence below is therefore: *read the supplied requirements → create `.venv` → install libraries into it → run the notebook with its Python*. The https://docs.astral.sh/uv/guides/projects/#project-structure[uv project guide] describes these files and their relationship.

== 1. Install uv on your own account

A *terminal* is a window where you enter commands. Open Terminal on macOS or Linux, or PowerShell on Windows. Enter these commands there, not in a Python prompt (`>>>`) or a notebook cell.

First check whether uv is already available:

[source,shell]
----
uv --version
----

If a version number appears, continue to step 2. Otherwise, use *only the command for your operating system* below. The official installer installs uv for your user account; run it without `sudo` or an administrator terminal. Python does not need to be installed beforehand.

.macOS or Linux
[source,shell]
----
curl -LsSf https://astral.sh/uv/install.sh | sh
----

.Windows — PowerShell
[source,powershell]
----
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
----

If you already use *WSL* (Linux inside Windows), use the Linux command in its terminal and keep the following steps in that same Linux environment.

Close and reopen the terminal, then run `uv --version` again. If you installed uv from a terminal inside VS Code, restart VS Code as well so that it can find the new command. These commands come from the https://docs.astral.sh/uv/getting-started/installation/[official uv installation guide].

== 2. Extract the bundle and open its folder

Click the green *Download bundle* button in the top navigation, or use xref:downloads.adoc[Downloads and releases]. *Extract the ZIP* into a new folder you can write to, for example `course-data-student` in Documents. Open the extracted folder, not the ZIP itself. Keep its directory structure: later notebooks read the data supplied beside them.

Install https://code.visualstudio.com/download[Visual Studio Code] if needed. In VS Code, choose *File → Open Folder* and select the extracted folder containing `pyproject.toml`. Then choose *Terminal → New Terminal*. This opens a terminal in that folder. If you use WSL, open the folder in a VS Code window connected to WSL.

Before continuing, check that the VS Code file explorer shows:

[source,text]
----
course-data-student/
    pyproject.toml
    uv.lock
    .python-version
    notebooks/
    datasets/
    README.md
----

The folder name may differ. What matters is that `pyproject.toml` and `uv.lock` are directly inside it. A file whose name starts with a dot may be hidden by your file manager.

* `pyproject.toml` lists the Python version and libraries needed by the course, including pandas, NumPy, Matplotlib and the notebook kernel.
* `uv.lock` records the exact library versions and their dependencies, so students install the same versions.
* `.python-version` asks uv to use Python 3.12.

These files are already supplied. You do not need to create a new project with `uv init` or install each library separately. See https://docs.astral.sh/uv/guides/projects/#project-structure[uv's explanation of project files] for more detail.

== 3. Create the virtual environment

A *virtual environment* is a folder containing a Python interpreter and a separate set of libraries for this project. Here it is named `.venv`. For example, this course can use one version of pandas while another project uses a different version, without the two installations interfering. Your notebooks and data stay outside `.venv`.

In the terminal opened at step 2, run:

[source,shell]
----
uv venv --python 3.12
----

uv uses an available Python 3.12 or downloads it if needed, then creates `.venv` inside the bundle folder. This step prepares the environment; pandas and the other course libraries are installed in the next step. If this folder already has a working `.venv`, skip this creation step.

We show creation separately to explain what happens. In fact, `uv sync` below also creates `.venv` if it is missing. See https://docs.astral.sh/uv/pip/environments/[uv's virtual environment guide].

== 4. Install the libraries from the bundle

Still in the same terminal, run:

[source,shell]
----
uv sync --locked
----

`sync` installs the libraries described by `pyproject.toml` and `uv.lock` into `.venv`. The first download can take a few minutes. `--locked` keeps the supplied versions: if the two files disagree, uv reports an error instead of rewriting the lockfile. See https://docs.astral.sh/uv/concepts/projects/sync/[uv's installation and lockfile guide].

Wait until the command finishes and the terminal prompt returns. Keep these files as supplied for the course. There is no separate pandas installation to perform.

== 5. Check which Python runs

Run these two commands from the bundle folder:

[source,shell]
----
uv run --locked python -c "import sys; print(sys.version); print(sys.executable)"
uv run --locked python -c "import numpy, pandas; print('NumPy:', numpy.__version__); print('pandas:', pandas.__version__)"
----

`uv run` runs a command using this project's environment. `python -c` executes the short Python code between the quotes. You should see:

* Python *3.12.x*;
* a Python path inside this folder's `.venv` (`.venv/bin/python` on macOS/Linux, or `.venv\Scripts\python.exe` on Windows);
* the NumPy and pandas versions specified in the bundle, with no import error.

There is no need to activate `.venv` manually when using `uv run`. In a notebook, choosing the correct kernel serves the same purpose: it selects which Python executes your code.

== 6. Open the notebook in VS Code

A *notebook* (`.ipynb`) contains text and Python code cells. Its *kernel* is the Python process that executes those cells and remembers variables between them.

. In VS Code's Extensions view, install *Python* (`ms-python.python`) and *Jupyter* (`ms-toolsai.jupyter`), both published by Microsoft.
. Keep the complete bundle folder open. Open `notebooks/foundations/python-pandas.ipynb` from its file explorer.
. At the notebook's top right, click *Select Kernel* (or the current kernel name). Choose *Python Environments*, possibly under *Select Another Kernel*, then the Python 3.12 interpreter in *this folder's `.venv`*. The bundle already installs `ipykernel`, which connects Python to the notebook editor.
. To check the selection, add a code cell and run the code below. The path must point inside the bundle's `.venv`, as in step 5.

[source,python]
----
import sys
import pandas as pd

print(sys.executable)
print(pd.__version__)
----

Then restart the kernel and use *Run All* to execute the supplied notebook from top to bottom. Restarting clears previous variables, so this checks that the cells work in their written order. In the worked sensor example, the mean should be about *21.3 °C*, using *3 available readings* and leaving *1 reading missing*.

Keep the notebook inside the bundle. Later lessons need its `datasets` folder. The https://code.visualstudio.com/docs/datascience/jupyter-notebooks[VS Code notebook guide] and https://docs.astral.sh/uv/guides/integration/jupyter/#using-jupyter-from-vs-code[uv guide for VS Code] illustrate this workflow.

== When you return for the next class

Open the same folder in VS Code, open the required notebook and select its `.venv` kernel. You do not need to reinstall uv or recreate the environment each time. Use `uv run --locked python ...` for terminal commands. If you download a new course bundle, extract it into a separate folder and repeat steps 3–6 there, keeping your previous work.

== If something goes wrong

[cols="2,4",options="header"]
|===
|What you see |What to check
|`uv: command not found`, or uv is not recognised
|Close and reopen the terminal (and VS Code if it was open during installation). Check the installer's message and retry `uv --version`.
|`No pyproject.toml found`
|Open the extracted folder that directly contains `pyproject.toml` and `uv.lock`, then open a new terminal there. Do not run setup from `notebooks/` or from inside the ZIP.
|A download fails
|Check your Internet connection and retry `uv sync --locked`. Keep the full error message if it fails again.
|The lockfile needs updating
|Use `pyproject.toml` and `uv.lock` from the same bundle. Keep the error for the instructor; do not remove `--locked` to hide the problem.
|`ModuleNotFoundError: No module named 'pandas'`
|Check that `uv sync --locked` completed, then check the notebook kernel path. A successful terminal import does not mean that the notebook has selected the same Python.
|`.venv` is absent from the kernel list
|Check that the full bundle folder is open and that the Python and Jupyter extensions are installed. Use *Python: Select Interpreter* from the command palette and select `.venv/bin/python` or `.venv\Scripts\python.exe`, then return to the notebook's kernel selector. With WSL, use a VS Code window connected to the same WSL environment.
|`FileNotFoundError` in a later lesson
|Keep the notebook under `notebooks/` in the extracted bundle, with `datasets/` alongside that folder.
|===

If you are still blocked after ten minutes of troubleshooting, record the command and its error for xref:readiness-check.adoc[the readiness check]. Use the xref:foundations/python-pandas.adoc[first pandas page] or work with a partner during class, then ask for setup support.

You are ready when the imports work in `.venv` and the first notebook runs from a restarted kernel. Continue with xref:session-pandas.adoc[the class slides and programme] or xref:foundations/python-pandas.adoc[Python and pandas: first steps].
