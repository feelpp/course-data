Pairs deliver a reproducible scientific or industrial analysis in a private GitHub Classroom repository. The project is worth 25%: 23 pair points and 2 individual-verification points. Block 13 provides an 80-minute clinic; the budget is 600 minutes (10 hours) of outside-class work per student, in addition to the clinic. Keep a time log and raise a likely overrun at a checkpoint so the question can be narrowed. The final compute path is bounded; a model catalogue is not required.

== Start at Block 5

The xref:downloads.adoc[student bundle] includes `templates/project-starter/` with a locked environment, input-contract example, toy data, tests and CI workflow. Copy the entire folder, including hidden files, into the assigned private Classroom repository and follow its README. The supplied toy check does not replace assessed scientific tests.

== Choice and scope

Choose one approved route:

* a supervised question using the Beijing air-quality or AI4I snapshot;
* an unsupervised station/profile question using Beijing or Dry Bean;
* an instructor-approved scientific dataset satisfying the same licence, privacy, offline, and size contract.

Define one primary question, unit of analysis, stakeholder or scientific use, success evidence, and explicit non-goal. A larger model catalogue is not a substitute for a defensible question and evaluation design.

== Required repository artifacts

* `README.md`: question, scope, commands, expected runtime, repository map, assessed commit;
* locked Python environment and passing CI;
* data registry entry, checksum, attribution, licence, schema and concise datasheet;
* reusable transformations and evaluation functions outside hidden notebook state;
* tests for key/cardinality, semantic constraints, one toy oracle, and one end-to-end smoke path;
* notebook or report with EDA, baseline, validation, method comparison, uncertainty/variation, failure analysis, and limitations;
* concise result/model card with intended and out-of-scope uses;
* `ai-notes/` record, or an explicit declaration that no AI assistance was used;
* tagged release built from the assessed commit.

== Method contract

The project must use at least one Core (P1) method appropriate to its question and compare it with an Essential (P0) baseline. Learned preprocessing, feature selection, and search belong inside the validation design. The final test data are used once for the final selected workflow. Optional Extension (P2) tools may be explored, but the required result and clean run must remain complete without them.

=== Approved Core (P1) evidence routes

[cols="3,4,4",options="header"]
|===
|Route |Required method evidence |Required challenge
|Stable regression |Stable least squares plus Ridge/Lasso or a probabilistic loss link. |Conditioning, residual structure, regularisation/generalisation stability.
|Classification/ensembles |Logistic baseline plus a controlled tree/forest/boosting comparison. |Class-conditional errors, threshold consequences, importance non-causality.
|PCA/clustering |Scaled PCA plus at least two clustering geometries. |Seed/resample stability, internal-score limits, domain interpretation.
|Performance-aware analysis |Typed Parquet artifact and projected/filtered analytical query. |Memory estimate, fair equality-tested benchmark, bounded engine conclusion.
|===

Feature selection/search may support any route, but it must remain inside the validation design. Each pair also answers one independent Core (P1) verification prompt selected from a different method family.

== Individual verification — 2 points

*A2-T8 — Individual verification — 2 points, Essential/Core (P0/P1).* Each student receives 5–8 minutes to explain, test, or modify a selected repository element. Full credit requires a correct explanation of the evidence chain and a safe small change. Appointments are separate from the 28 contact hours and the final control. The instructor publishes the schedule before project submission and reserves 5–8 minutes per student plus transitions; for a cohort of N students this is 5N–8N minutes before transitions. The verification may produce an individual adjustment when authorship or understanding differs materially within the pair.

== Delivery checkpoints

. Block 5: question, data source, licence, roles and split design proposed with the starter.
. Block 7: pull request with the baseline, quality contract and first tests.
. Block 9: bounded method comparison and validation design agreed.
. Block 13 review with draft result card and reproducibility evidence.
. Tagged release and individual verification.

The assessed release should execute within 10 minutes and below 4 GiB on the reference environment. Timing itself earns no marks.
