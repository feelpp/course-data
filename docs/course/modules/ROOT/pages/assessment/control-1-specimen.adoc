This specimen fixes the task structure and expected depth. The live control uses different values and may use a regression rather than classification context, while preserving the same evidence and difficulty.

== Conditions

* 70 minutes, individual, 20 points, AI Mode A.
* CPU-only provided environment and offline data bundle.
* Documentation bundled with the environment is allowed.
* Submit the completed notebook/script and generated `audit.json`.

== Scenario

An industrial test bench records one row per machine cycle in `cycles.csv`. `machines.csv` supplies one metadata row per machine. The goal is to predict whether a cycle requires inspection. The bundle contains timestamps, numeric sensor measurements, a categorical machine family, missing values, repeated identifiers, inconsistent temperature units, and one failure-derived column that would reveal the target.

The source card states that the tables are synthetic, contain no personal data, and may be used for teaching. Your report must not claim measured performance for a real factory.

== Tasks and points

=== A1-T1 — Problem and join contract — 4 points, Essential (P0)

. State the unit of analysis, target, and expected key uniqueness in both tables. (1)
. Predict the valid join cardinality before executing it. (1)
. Implement a validated join and prove that it neither multiplies nor silently loses cycle rows. (2)

=== A1-T2 — Data-quality decisions — 4 points, Essential (P0)

. Report type/unit, missing, duplicate, impossible-range, and anomalous-value findings. (2)
. Apply justified repairs without converting rare valid events into errors. (2)

=== A1-T3 — Executable checks — 3 points, Essential (P0)

Write at least two focused assertions or tests. One must protect identity/cardinality and one must protect a semantic constraint such as units, range, category, or target role.

=== A1-T4 — Leakage-safe baseline — 5 points, Essential (P0)

. Identify and exclude the failure-derived leaking column, explaining the consequence. (1)
. Create the split before any learned imputation, encoding, or scaling. State whether stratification, grouping, or time order is required. (1)
. Build numeric and categorical preprocessing inside a fitted pipeline. (2)
. Compare with an appropriate dummy baseline. (1)

=== A1-T5 — Metric, failure, and limits — 4 points, Essential (P0)

. Select a metric from the stated inspection/missed-failure consequences and interpret it in context. (2)
. Identify one observed failure mode. (1)
. Write one concise limitation covering synthetic data and external validity. (1)

== Critical cap

Fitting learned preprocessing on the complete/test data or retaining target-derived information limits Task 4 to 1/5 unless the error is identified and corrected. An unvalidated row-multiplying join limits the join evidence in Task 1 to 1/4. Other correct evidence remains eligible for credit.

== Acceptance and tolerances

Counts and join assertions are exact. Seeded metric checks use an absolute tolerance of 0.01. Wall-clock speed is not graded. The reference solution completes in under five minutes on the xref:technical-contract.adoc[reference environment].
