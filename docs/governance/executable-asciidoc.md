# Executable AsciiDoc contract

## Status

Accepted and implemented for every required P0/P1 notebook-producing lesson. The optional JAX extension remains Python-authored because it uses solution-cell metadata outside the current public page contract.

## Decision

AsciiDoc is the canonical source for eligible learning sequences that combine English prose, mathematics, executable Python, result interpretation, and public exercises. The same page produces:

1. an Antora HTML page with selected trusted results embedded by `@feelpp/asciidoctor-extensions`;
2. an unexecuted student notebook generated by `asciidoctor-jupyter` and independently executed in CI.

Reusable loaders, algorithms, validators, metrics, and plot helpers remain canonical in tested Python modules. Dataset provenance remains canonical in dataset manifests. Generated notebooks, executed notebooks, HTML, images, and archives are never edited as source.

## Eligibility

AsciiDoc-first generation is required for new guided P0/P1 pages unless the course lead records a justified notebook-native exception in `curriculum.yml`. Legitimate exceptions include required widget state, assessment-specific cell metadata, or another feature that cannot be represented safely by the reviewed converter.

Existing notebook-native material migrates page by page. No existing notebook builder is removed until page/notebook parity, clean execution, accessibility, and human review pass.

## Page contract

An executable notebook-producing page declares:

```adoc
:page-jupyter:
:dynamic-blocks:
:dynamic-blocks-strict:
:dynamic-blocks-timeout-seconds: 60
:dynamic-blocks-max-output-bytes: 5242880
:dynamic-python-interpreter: python3
:dynamic-python-isolate-user-site:
:jupyter-language-name: python
:jupyter-language-version: 3.12
:jupyter-kernel-name: python3
:jupyter-kernel-language: python
```

Every required executable block has an explicit ID and fails on error:

```adoc
[#sample-mean]
[%dynamic%open,python,fail-on-error=]
----
print("concise deterministic evidence")
----
```

Required blocks must be deterministic, CPU-compatible, offline, bounded, and free of private data. Every result is followed by its meaning, units where applicable, expected numerical scale, and at least one limitation.

AsciiDoc callout markers are forbidden inside canonical Python blocks until the reviewed converter adapter removes them from generated code while preserving the explanatory list. Version `0.7.0` currently leaves markers such as `<1>` in notebook cells.

## Strict execution policy

- Required blocks fail the build on any Python error.
- Antora runs inside the locked `uv` environment.
- The configured interpreter is launched directly without a shell.
- The Python process receives an allowlisted environment; arbitrary tokens and credentials are removed.
- Required course pages use an isolated home, Python user-site, IPython directory, Matplotlib configuration, and temporary directory. The temporary workspace is removed after success, failure, timeout, or excessive output.
- Required P0/P1 blocks do not access the network.
- The execution job has no deployment token, release token, private assessment checkout, or secrets.
- Each page has an enforced time limit and aggregate output limit before production migration.
- Absolute paths, undeclared subprocesses, credentials, personal data, live assessments, and instructor solutions are forbidden.
- Randomness, splits, ordering, precision, plotting style, locale, timezone, and data snapshots are controlled where they affect results.
- Cached output is never authoritative unless its key includes source, predecessors, environment, data, and extension identities.

The extension returns structured failure codes for invalid configuration, missing interpreters, timeouts, output-limit violations, failed Python blocks, abnormal process termination, and malformed execution records. It is a trusted-code executor, not an operating-system sandbox. Runner or container isolation and credential-free jobs remain mandatory.

## Output policy

Text and scalar results may be embedded when concise. Scientific figures require a deterministic renderer, alternative text, caption, labelled axes and units, non-colour encoding, sample/population context, and a textual interpretation. Interactive results require an offline, keyboard-accessible static alternative.

Matplotlib `3.11.1` output is approved when the block declares `output=matplotlib`, supplies non-empty `figure-alt` text, and uses a caption and labelled axes with units where applicable. The Feel++ Asciidoctor extension captures deterministic inline PNG output, closes figures after capture, and provides an offline result. General IPython rich output remains unapproved until its MIME types receive equivalent validation. A screenshot or unexplained PNG is not an acceptable substitute.

## Resource and attachment layout

Generated website attachments mirror the source page inside its Antora module:

```text
modules/<module>/pages/<relative-path>.adoc
modules/<module>/attachments/<relative-path>.ipynb
```

For example:

```text
modules/ROOT/pages/foundations/data-lifecycle.adoc
modules/ROOT/attachments/foundations/data-lifecycle.ipynb
```

The UI displays a notebook link only after the Antora content catalog confirms the attachment. The student ZIP may expose the same artifact as `notebooks/ROOT/foundations/data-lifecycle.ipynb`.

## Metadata and manifest

Generated notebook metadata conforms to `schemas/asciidoc-notebook-metadata.schema.json`. The deterministic source/artifact inventory conforms to `schemas/asciidoc-notebook-manifest.schema.json`.

The manifest contains no generation timestamp. Source and output digests, tool versions, resource identities, page metadata, and code-block digests provide the audit trail.

## Extension ownership

- `feelpp-asciidoctor-extensions` owns trusted execution, strict failures, interpreter selection, limits, rich output, and result blocks.
- `feelpp-antora-extensions` owns page discovery, notebook conversion orchestration, content-catalog attachment insertion, resolved URLs, and manifests.
- `antora-ui` renders only confirmed notebook resources and accessible result controls.
- `asciidoctor-jupyter` owns AsciiDoc-to-notebook conversion. Generally useful converter changes should be proposed upstream; a small tested adapter may normalise metadata, cell IDs, unsupported-node reporting, and unexecuted counts while awaiting an upstream release.
- `course-data` owns curriculum, eligibility, security policy, parity validation, execution profiles, accessibility, assessment boundaries, and release gates.

No course release may depend on an unpublished local checkout.
